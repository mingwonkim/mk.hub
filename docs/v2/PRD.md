# MK.HUB 미래 도시 개편 PRD

## 목적과 범위
개인 저장소의 데이터 탐색·작성·관리를 유지하면서 미래 대도시 공간을 이동하는 PC 중심 웹으로 개편한다. 이번 제작 단위는 도시 전경 스틸 한 장뿐이며 사용자 확인 전 다음 이미지·영상·UI를 제작하지 않는다.

## 확정 방향
- PC 우선, 모바일 고급 연출은 후속. 모든 방문·섹션 이동에서 전체 경로 연출, 첫 진입보다 이후 이동은 짧게.
- 어두운 도시와 밝은 피사체, 흰 안개·핑크 구름을 함께 사용. 단조로운 네온 야경이나 세피아 필름톤으로 한정하지 않는다.
- 고층 빌딩·대형 전광판·비행선. AI 공학·의류디자인·K-pop 작곡 취향을 데이터 격자·패션 사진 구성·스튜디오로 반영.
- 작업 패널은 유리, hover/focus-within에서 불투명. 입력 중 불투명 유지. 터치는 읽을 수 있는 표면 우선.
- 모든 입력·목록·저장 상태·모달·잠금 화면은 공통 시스템. 기본 상태에서도 가독성 확보.
- 사용자가 영상 2개 제한·크레딧 30% 사용 상한 해제. 비용 사전 확인·통보, 사용 기록 유지. 자동 구매 금지.

## IA와 공간
Hub: 도시 접근과 최근 자료/할 일. Vault: 빌딩 창문을 지나 우드 가구·식물·침대·서재가 있는 개인 사무실. Music: 소속사 건물의 작곡 작업실. Morning Brief: 드론 배달. Todo: 글래스 착용 시점의 캘린더·할 일. Gallery: 전시관으로 이동 후 교체 가능한 큰 사진 프레임. Settings: 기존 설정.

## 실제 코드와 데이터
정적 HTML/CSS/JS, index.html SPA, GitHub Pages. Expo 전환 계획 없음.
Firestore mk_app/data: memos, folders, files, file_folders, todos, music_notes, fav_songs, playlists, playlist_songs, gallery, briefs.
hub_memo/hub_memo2 문서 유지. mk_files/mk_drawings 비공개 Storage 경로 유지.
MKVault 서버 패턴 인증·이메일 복구·소유자 규칙 보존. 실제 doOpenApp에서 files는 memo로 연결됨.
음감 훈련·코드 사전 iframe과 기존 갤러리 1~5picture 저장 키 보존. 109개 슬롯·59개 문구는 기존 기록이며 구현 전에 다시 대조.
Brief 본문 생성은 서버 담당, 새 뉴스 저장 기능은 기존 지원 범위부터 확인한다.
운영 데이터를 프리뷰 샘플이나 공개 이미지로 사용하지 않는다.

## 성공 기준
현재: 도시 전경 스틸 1장, 큰 도시 스케일·비행선·전광판·명암 균형·다음 카메라 이동 가능 구도 확인 후 사용자 검토.
후속: 1440x900·1024x768, 모바일 390 너비, 기본/hover/편집 가독성, 작은 글자 대비 4.5:1, 저장 후 재접속·사진 교체·잠금·음악 도구 회귀 확인.
모션은 건너뛰기/줄이기 지원, 영상 로드 실패에도 저장소 접근 가능. 읽고 쓰는 중 카메라 안정화.

## 작은 단위 순서
도시 스틸 → 사용자 확인 → 도시 이동 영상 → 확인 → Vault 실내 스틸 → 확인 → 연결 영상 → 확인 → 유리 패널 한 개 → 확인 → 기능별 확장. 각 단위 완료 즉시 기록.
